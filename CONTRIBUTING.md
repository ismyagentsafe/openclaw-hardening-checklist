# Contributing

Thanks for helping keep this checklist accurate.

## What we accept

- **Corrections:** a setting renamed, a default changed, a command that no longer exists. Please link the official doc page or release note that shows the change.
- **New items** that are in the official OpenClaw docs or that `openclaw security audit` checks. Each item must link to its source.
- **Clearer wording** for people who aren't security specialists.

## What we don't accept

- Product promotion or links to paid tools. The one link to the maintainer's free check stays at the bottom, and that's it.
- Items without a source, or advice that contradicts the official docs.
- Wording that promises a setup is "safe", "secure" or "unhackable". Checklists reduce risk; they don't remove it.

## How

1. Open an issue or a PR against `README.md`.
2. Keep each item a single `- [ ]` line, if you can, with the doc link inline.
3. Update the "Last checked against the docs on" date if you re-verified a section.
4. Don't include real tokens, keys, hostnames or IPs in examples. Use placeholders.

## Disclosure

The maintainers (Is My Agent Safe, Your Evenings Ltd) use AI agents to draft and check changes. Every change links to its source so anyone can verify it. Security issues in OpenClaw itself belong to the OpenClaw project: see <https://github.com/openclaw/openclaw/security>. Don't report them here.
